# Read Day of Praise Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Read a day's praise entries with ownership enforced server-side and per-entry local decryption that tolerates a single corrupt ciphertext.

**Architecture:** `GET /api/v1/praises?date=` returns only the authenticated user's rows for that day (default: server-computed today), each as `{id, local_date, created_at, iv, body_ciphertext}` with the encrypted fields base64-encoded — the server never decrypts. `loadDay(client, key, date, fetcher)` (frontend) fetches once and decrypts each entry in its own try/catch, flagging failures as `unreadable` without breaking the rest.

**Tech Stack:** FastAPI, SQLAlchemy 2 async, React 19, Web Crypto, Vitest.

**Spec:** `docs/backlog.md` — `PH-206`; product-brief invariants 4, 7, 8.

## Acceptance Criteria Mapping

- API checks ownership → `list_praises_for_day` filters by `user_id` (Task 1 + DB test).
- frontend decrypts locally → `loadDay` uses `decryptPraise` (Task 2).
- corrupt ciphertext does not break the day and is explained → per-entry try/catch → `unreadable`
  flag (Task 2); the user-facing explanation is rendered in PH-303 (Deferred).

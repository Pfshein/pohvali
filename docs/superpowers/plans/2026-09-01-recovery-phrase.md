# Recovery Phrase v1 Implementation

**Goal:** дать пользователю явный способ сохранить AES-ключ и восстановить его на другом
устройстве, не передавая ключ backend.

**Spec:** `docs/backlog.md` — `PH-202 · P0 · Recovery phrase v1`.

## Формат

`pohvala-v1.<payload>.<checksum>`

- `payload` — 32 байта AES-256 key в unpadded base64url (43 символа);
- `checksum` — первые 8 байт SHA-256 от строки `pohvala-v1:<payload>`, hex lowercase;
- версия проверяется до импорта ключа;
- checksum проверяется до записи в storage;
- окружающие пробелы и перенос строки при вставке допускаются, внутренние — нет.

## Реализация

- [x] Чистые client-side функции export/import с versioned format и checksum.
- [x] Round-trip тест: исходный ключ шифрует, импортированный ключ расшифровывает.
- [x] Повреждённая, неизвестная или неверно подписанная фраза не меняет storage.
- [x] UI показывает фразу только после отдельного действия пользователя.
- [x] Импорт сохраняет ключ через `KeyStorage` и сразу заменяет активный ключ сессии.
- [x] Фраза и ключ не передаются в `fetch` или backend API.

## Ограничения v1

Формат рассчитан на надёжное копирование и вставку, а не на ручной ввод слов по памяти.
Backend не хранит копию ключа и не может восстановить потерянную фразу. Импорт корректной
фразы от другого ключа технически допустим, но старые записи с ним не расшифруются.

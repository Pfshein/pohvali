# Дизайн PH-504: настройки напоминаний

**Дата:** 2026-09-02
**Статус:** утверждён для реализации

## Цель

Мягкий one-time offer напоминаний при прямом входе в Mini App и постоянная
секция настроек. Отказ никогда не переспрашивается; тексты спокойные и не
содержат личных записей.

Бэкенд-эндпоинты уже существуют (`GET/PUT /api/v1/reminders`,
`{enabled, dm_available}`) — задача в основном фронтендовая, плюс маркер входа.

## Отличение «прямого входа»

Кнопка в вечернем напоминании уже открывает Mini App (`AiogramReminderSender`).
Её URL получает `?from=reminder`: пользователь, пришедший из напоминания,
предложение не увидит — он уже получает их. Функция `reminder_entry_url`
чистая и тестируется; `main.py` использует её при сборке sender'а.

## One-time offer

- Показывается один раз при первом прямом входе (`ReminderOffer`): спокойный
  вопрос про тихое вечернее сообщение (~22:00), кнопки «Да, напоминай» /
  «Не нужно».
- Ответ сохраняется локально в Telegram CloudStorage (с фолбэком на
  device-local, как onboarding-флаг): `pohvala.reminder_offer.answered`.
  Непустое значение = отвечено → предложение больше не показывается никогда.
- Ответ применяется и на сервере: «Да» → `PUT {enabled: true}` (явное
  согласие), «Не нужно» → `PUT {enabled: false}`. Ошибка синхронизации не
  блокирует фиксацию ответа: предложение скрывается, а живое состояние видно в
  настройках, где переключатель можно перевключить.
- Ошибка сохранения локального флага оставляет предложение с спокойной
  подсказкой повторить — иначе «отказ» потерялся бы и спросили бы снова.

## Секция настроек

`ReminderSettings` в главном экране: заголовок «Напоминания», описание «одно
тихое сообщение около 22:00, если за день ещё нет записи», переключатель
`role="switch"` на `GET/PUT /api/v1/reminders`. Если `dm_available=false`,
показывается честная подсказка: чтобы напоминания приходили, достаточно один
раз открыть чат с ботом (ограничение Telegram). Состояние загрузки и ошибки —
спокойные, без давления.

## Инварианты

- Тексты не содержат streak/pressure-слов (тон-аудит PH-604 продолжает
  сканировать новые файлы) и никогда не упоминают содержимое записей.
- Offer не показывается при входе из напоминания и после любого ответа.
- Сервер остаётся источником истины для `enabled`; локальный флаг управляет
  только показом предложения.
- Никаких новых эндпоинтов/таблиц: только существующий reminders API.

## Приёмка

1. При прямом входе предложение показывается один раз; при входе
   `?from=reminder` — не показывается.
2. Любой ответ («да»/«нет») скрывает предложение навсегда; «нет» выключает
   напоминания на сервере.
3. Переключатель в настройках отражает и меняет `enabled`; при
   `dm_available=false` показана подсказка про чат с ботом.
4. Все тексты проходят тон-аудит; проверено тестами (транспорт, логика
   показа, компоненты, URL-хелпер).

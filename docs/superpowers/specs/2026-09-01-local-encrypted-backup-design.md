# Дизайн PH-704A: локальный зашифрованный backup

**Дата:** 2026-09-01
**Статус:** утверждён для закрытой альфы

## Цель

Раз в сутки создавать на production VPS проверяемую зашифрованную копию
PostgreSQL с RPO не более 24 часов. Решение должно защищать от ошибочного
удаления данных, неудачной миграции и повреждения основной Docker volume, не
добавляя новый долгоживущий сервис.

PH-704A не защищает от потери всего VPS, компрометации root или удаления
аккаунта у хостинг-провайдера. Перед публичным запуском PH-704B добавит выгрузку
этих же зашифрованных файлов в приватное внешнее object storage. До PH-704B
исходная задача PH-704 остаётся незакрытой.

## Архитектура

Host-side Bash-скрипт запускается `systemd timer`. Он вызывает `pg_dump` внутри
существующего контейнера `postgres` через `docker compose exec`, передаёт custom
archive напрямую в `age` и атомарно публикует только завершившийся файл:

```text
PostgreSQL container
    -> pg_dump --format=custom
    -> stdout pipe
    -> age encryption
    -> .partial file
    -> atomic rename to *.dump.age
```

Незашифрованный dump не записывается на диск. На VPS хранится только публичный
`age` recipient; приватный identity остаётся на компьютере администратора и в
менеджере секретов. Для восстановления зашифрованный архив копируется на
администраторский компьютер и разворачивается в одноразовый PostgreSQL container
без портов и без подключения production volume.

## Файлы и интерфейсы

- `ops/backup/backup.sh` — создание архива, атомарная публикация и retention.
- `ops/backup/restore-drill.sh` — восстановление в одноразовый PostgreSQL 17 и
  проверка обязательных таблиц.
- `ops/backup/backup.env.example` — несекретные host-side настройки.
- `ops/backup/pohvala-backup.service` — одноразовый systemd unit.
- `ops/backup/pohvala-backup.timer` — ежедневный запуск с `Persistent=true`.
- `docs/backup.md` — установка, проверка, восстановление и ограничения.

`backup.sh` читает следующие переменные окружения:

| Переменная | Default | Назначение |
| --- | --- | --- |
| `POHVALA_PROJECT_DIR` | `/opt/pohvali` | Каталог с `compose.yaml` |
| `POHVALA_BACKUP_DIR` | `/var/backups/pohvali/postgres` | Каталог архивов |
| `POHVALA_AGE_RECIPIENT_FILE` | `/etc/pohvali-backup/recipients.txt` | Публичные age recipients |
| `POHVALA_BACKUP_RETENTION_COUNT` | `7` | Число последних успешных архивов |
| `POHVALA_BACKUP_LOCK_FILE` | `$POHVALA_BACKUP_DIR/.backup.lock` | Блокировка параллельного запуска |

## Инварианты безопасности

- Скрипт работает с `set -Eeuo pipefail`: ошибка `pg_dump` не может быть скрыта
  успешным завершением `age`.
- Каталоги проекта, архивов и recipient-файл задаются абсолютными путями.
- Retention принимает целое число от 2 до 365 и удаляет только файлы с именем
  `pohvala-postgres-*.dump.age` внутри заданного backup-каталога.
- Retention выполняется только после успешного создания непустого архива.
- Временный `.partial` удаляется при любой ошибке.
- Финальный архив имеет режим `0600`, backup-каталог — `0700`.
- Логи содержат только результат, имя файла и размер; содержимое dump, Telegram
  ID, ciphertext и секреты не выводятся.
- На VPS отсутствует приватный `age` identity.
- Restore drill создаёт контейнер без опубликованных портов и всегда удаляет его
  при успехе, ошибке или прерывании.

## Расписание и хранение

- Timer запускается каждый день в `03:15 UTC` и догоняет пропущенный запуск после
  выключения VPS.
- Хранятся последние 7 успешно завершённых архивов независимо от пропущенных
  дней или ручных запусков.
- Локальный архив находится вне `postgres_data`, поэтому удаление или порча
  Docker volume не удаляет backup.

## Приёмка PH-704A

1. Успешный запуск создаёт один непустой `*.dump.age`; plaintext dump и
   `.partial` отсутствуют.
2. Ошибка `pg_dump` или `age` возвращает ненулевой код, удаляет partial и не
   запускает retention.
3. После успешного запуска остаются семь последних архивов, посторонние файлы не
   удаляются.
4. Параллельный запуск отклоняется блокировкой.
5. Реальный restore drill расшифровывает выбранный архив в новый пустой
   PostgreSQL 17, `pg_restore --exit-on-error` завершается успешно и обязательные
   таблицы `alembic_version`, `users`, `praises` существуют.
6. В `docs/backup.md` сохранены команды установки timer, ручного запуска,
   проверки свежести и restore drill.
7. `compose.yaml` по-прежнему содержит четыре долгоживущих сервиса; backup —
   host-side one-shot job.

## PH-704B перед публичным запуском

Позднее после атомарного создания локального файла добавляется отдельный шаг
загрузки в приватный bucket с выключенным public access. Схема dump, шифрование,
имена файлов и restore script не меняются. PH-704B отдельно определит провайдера,
credentials с правами только на backup-prefix, bucket retention и проверку
восстановления при полной недоступности VPS.

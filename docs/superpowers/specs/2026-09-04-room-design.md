# Дизайн PH-901: главная «Комната» на React + PixiJS

**Дата:** 2026-09-04
**Статус:** утверждён для каркаса первого этапа

## Цель

Заменить верхнюю часть главного экрана спокойной почти полноэкранной комнатой:
маскот рядом с базовым креслом, крупное действие «Похвалить себя», вторичное
действие «Обустроить» и компактные входы в календарь и профиль. Первый этап
создаёт технический фундамент без сложных анимаций, магазина мебели и серверной
синхронизации комнаты.

Комната — эмоциональная оболочка существующего сценария похвалы, а не игра с
обязательным прогрессом. Она не вводит streak, потерю предметов, таймеры,
соревнование или наказание за отсутствие записей.

## Место в текущей архитектуре

Репозиторий остаётся модульным монолитом из React/Vite frontend, FastAPI backend,
PostgreSQL и Caddy. На первом этапе меняется только frontend:

- `SessionRoot` по-прежнему создаёт Telegram-сессию, ключ шифрования и API-адаптеры;
- `App` по-прежнему владеет пользовательским сценарием похвалы, календарём,
  коллекцией, напоминаниями и privacy-действиями;
- новый вертикальный срез `frontend/src/features/room` владеет моделью комнаты,
  каталогом предметов, локальной сериализацией и Pixi-рендером;
- React рисует доступные элементы управления и диалоги поверх canvas;
- PixiJS рисует только мир комнаты и обрабатывает pointer-события внутри него;
- backend в PH-901 не получает таблиц, endpoint'ов и содержимого комнаты.

Существующий `StarArcHero` не удаляется каркасом: переключение главного экрана на
`RoomHome` выполняется отдельным интеграционным шагом после проверки UX. Это
уменьшает риск для уже работающего пути создания похвалы.

## Зафиксированный стек

- React 19 и React DOM — оболочка приложения, состояние сценария и доступный UI;
- TypeScript в текущем strict-режиме репозитория;
- PixiJS 8 — canvas/WebGL/WebGPU-рендер комнаты;
- Vite 8 — существующая сборка;
- Vitest — чистая модель, сериализация и lifecycle-контракты.

`@pixi/react` в первый этап не входит. Тонкий императивный адаптер делает границу
владения очевидной: React передаёт снимок данных, Pixi синхронизирует display
objects. Это не мешает перейти на React renderer позднее, потому что модель и
каталог от Pixi не зависят.

## Границы модулей

```text
SessionRoot (Telegram/API/crypto)
  └─ App (похвала, календарь, панели)
      └─ RoomHome (DOM-команды и компоновка)
          └─ RoomCanvas (React lifecycle bridge)
              └─ RoomRuntime (mount/update/resize/destroy)
                  └─ PixiRoomRenderer (только PixiJS)

RoomHome ── RoomState/RoomItem ── catalog + placement + serialization
                                  (не импортируют React или PixiJS)
```

Зависимости направлены внутрь: `pixi` зависит от `model` и `catalog`, но модель
никогда не импортирует PixiJS, DOM, React, API-клиенты или storage.

## Модель данных

```ts
type NormalizedPoint = { x: number; y: number };
type RoomZoneId = "wall" | "floor" | "fixed";
type RoomLayer = "background" | "wall" | "floor" | "furniture" | "mascot" | "foreground" | "effects";

interface RoomItem {
  id: string;                 // id экземпляра, стабилен после сохранения
  templateId: string;         // ссылка на каталог, не на URL ассета
  position: NormalizedPoint;  // x/y в диапазоне 0…1
  scale: number;              // относительный scale экземпляра
  rotation: number;           // радианы
  layer: RoomLayer;
  zIndex: number;             // порядок только внутри логического слоя
  zoneId: RoomZoneId;
  locked: boolean;            // нельзя перетаскивать в обычном режиме
}

interface RoomState {
  schemaVersion: 1;
  items: RoomItem[];
}
```

Нормализованные координаты не зависят от размера Telegram viewport. Экранная
позиция вычисляется только рендерером: `px = x * width`, `py = y * height`.
При resize меняется проекция, а не данные.

## Слои и z-index

Глобальный порядок фиксирован константой:

| Слой | База | Назначение |
|---|---:|---|
| `background` | 0 | стены, свет, фон |
| `wall` | 1000 | настенный декор |
| `floor` | 2000 | ковры и напольные подложки |
| `furniture` | 3000 | кресло и мебель |
| `mascot` | 4000 | активный спутник |
| `foreground` | 5000 | декор перед персонажем |
| `effects` | 6000 | будущие частицы/glow |

Итоговый `sortableChildren`-порядок равен базе слоя плюс ограниченный локальный
`zIndex`. Стабильный `id` разрешает ничьи. Предмет не может локальным z-index
перепрыгнуть в другой слой.

## Placement zones

В PH-901 зоны — нормализованные прямоугольники:

- `wall`: `x 0.05…0.95`, `y 0.08…0.52`;
- `floor`: `x 0.08…0.92`, `y 0.55…0.94`;
- `fixed`: `x 0…1`, `y 0…1`, только для системных элементов.

Каталог объявляет допустимую зону шаблона. На pointer move позиция визуально
ограничивается зоной; на pointer up React получает уже нормализованную валидную
позицию. Полигональные зоны, collision и привязка к поверхности — совместимые
расширения контракта, но не часть первого этапа.

## Каталог, asset manifest и registry

Добавление предмета не требует менять `RoomCanvas` или `PixiRoomRenderer`:

1. `RoomCatalog.templates` получает декларативный `RoomItemTemplate`;
2. `RoomCatalog.assets` связывает `assetId` с texture URL либо procedural renderer;
3. `instantiateRoomItem(templateId, instanceId, overrides)` создаёт сериализуемый
   экземпляр;
4. renderer registry создаёт Pixi `Container` для типа ассета.

URL не сохраняется в `RoomState`: ассет можно заменить без миграции пользовательских
комнат. Начальное кресло процедурное. `RoomHome` принимает `{code, label,
assetPath}` активного маскота и строит catalog из авторитетного `assetPath`
`MascotCollection`; поэтому маскоты, добавленные admin-командой и отдаваемые через
`/api/v1/mascots/{code}/image`, не требуют frontend hardcode.

## Pixi lifecycle

`RoomCanvas` создаёт ровно один `RoomRuntime` на DOM-host:

1. `mount(host, initialState)` создаёт `Application`, дожидается `app.init`,
   добавляет canvas и строит сцену;
2. `update(state)` выполняет keyed diff по `RoomItem.id`, а не пересоздаёт сцену;
3. `resize(width, height)` вызывается из `ResizeObserver`, обновляет renderer,
   hit area, фон и проекцию координат;
4. `destroy()` снимает observer/listeners, уничтожает display objects и
   `Application`; завершившийся после unmount асинхронный `init` тоже уничтожается.

В React StrictMode повторный mount/unmount безопасен. Pixi-объекты и listeners не
попадают в React state.

## Pointer events

- Интерактивны только незаблокированные предметы в режиме обустройства.
- Используются Pixi `pointerdown`, `globalpointermove`, `pointerup`,
  `pointerupoutside` и `pointercancel`, одинаковые для touch и mouse; drag
  привязан к инициировавшему `pointerId`.
- Нативные `canvas.pointercancel` и `window.blur` возвращают display object к
  последней сохранённой позиции; второй pointer не может перехватить активный drag.
- Во время drag renderer обновляет display object для плавности; доменное
  состояние коммитится один раз на drop через `onItemMove(id, point)`.
- Координата проходит `screen → normalized → grab offset → clampToZone`, поэтому
  объект не прыгает центром под палец.
- Кнопки «Похвалить себя», «Обустроить», календарь и профиль остаются DOM-кнопками:
  у них есть семантика, focus и screen-reader labels без canvas-дублей.

## Сериализация и хранение

Формат — JSON с `schemaVersion: 1`. Десериализатор проверяет форму, конечность
чисел, диапазоны, известные template/layer/zone и уникальность `id`. При ошибке
вся сохранённая строка отвергается, а UI открывает безопасную стартовую комнату.

В PH-901 storage adapter использует локальное Telegram CloudStorage с fallback
на `localStorage`, по образцу onboarding, но сам адаптер внедряется интерфейсом.
Синхронизация с backend — отдельная задача после подтверждения продукта; личные
тексты похвал в room state не попадают.

## Стартовое состояние

`createStarterRoom(mascotCode, catalog)` создаёт два экземпляра:

- `chair.basic` в `furniture`, зона `floor`, позиция `(0.62, 0.78)`;
- `mascot.{activeCode}` в `mascot`, зона `floor`, позиция `(0.43, 0.80)`.

Комната визуально имеет только спокойные стену/пол, кресло и текущего маскота.
Если texture маскота не загрузилась, renderer показывает нейтральный placeholder,
а основное действие остаётся доступным.

## Расширяемость

- Анимации получают отдельный `RoomSystem` с `update(deltaMs, context)` и
  регистрируются в runtime; `RoomItem` не хранит текущий кадр.
- Частицы живут только в слое `effects`, краткоживущи и не сериализуются.
- Реакция на сохранённую похвалу приходит как одноразовая команда/event, а не как
  новое поле постоянного состояния.
- Рост растения хранит только дискретную продуктовую стадию; tween между стадиями
  остаётся представлением.
- Новые версии JSON добавляются через миграции `vN → vN+1`, без распознавания по
  набору полей.

## Доступность и производительность

- Canvas декоративно-интерактивный, но все продуктовые команды дублируются DOM;
- при `prefers-reduced-motion` будущие idle/tween отключаются;
- resolution ограничен `min(devicePixelRatio, 2)`;
- texture загружаются один раз через Pixi Assets, экземпляры уничтожаются явно;
- resize не сериализует и не меняет room state;
- целевой первый кадр комнаты не блокирует открытие composer.

## Границы PH-901

Входят: модель, слои, зоны, каталог, asset manifest, starter state,
сериализация, runtime lifecycle, responsive canvas, pointer drag, процедурное
кресло, существующий активный маскот и `RoomHome` как изолированный UI-каркас.

Не входят: backend persistence, магазин мебели, инвентарь, collision, сложные
анимации, частицы, звук, редактирование масштаба/поворота, аналитика и удаление
существующего главного экрана до UX-приёмки.

## Приёмка

1. Модель и JSON не импортируют React/Pixi и проходят unit-тесты.
2. Один template превращается в любое число независимых экземпляров.
3. Координаты переживают resize без изменения данных; drag не выходит из зоны.
4. Порядок слоёв детерминирован и z-index не пересекает границу слоя.
5. Runtime корректно проводит `mount/update/resize/destroy`, включая StrictMode.
6. RoomHome показывает пустую комнату, маскота/кресло и четыре доступные DOM-команды.
7. Текущие сценарии похвалы, календаря, privacy, onboarding и маскотов не меняют API.
8. `npm run check` проходит после интеграционного шага.
